# Mikee AI — sales assistant

Mikee AI is a chat assistant on mikeegadget.com.ng. It answers shopping questions from the live Supabase catalogue and the store's own policies, qualifies leads, and hands customers to a person on the website or on WhatsApp.

**Current state:** simulation mode (rule-based, ₦0 AI cost). The OpenAI provider and the WhatsApp Cloud API adapter are built and tested, but both are switched off.

## 1. Findings from the existing site (checked before building)

| Area | What exists | How Mikee AI uses it |
|---|---|---|
| Front end | Static HTML generated by Node scripts (`npm run build`); Vite is used only for local dev. Shared scripts are injected by `scripts/apply-experience.mjs`. | The launcher is injected there on every page except checkout, cart and admin. The chat code loads only when the visitor opens it. |
| Catalogue | `checkout_inventory` read through `rpc/shop_deal_catalogue`; `commerce/deals.mjs → pricedVariant` applies Hot Deal prices; product pages and approved photos are in `commerce/merchant-products.mjs`. | The same RPC and `pricedVariant` are used, so chat prices match the website. Disabled variants, `reviewRequired` variants and variants without a valid price are excluded. |
| Delivery | `shop_delivery_rates` (admin-edited), with `seedRows()` as fallback. | Gives the exact fee for an LGA or state. If a fee isn't set (e.g. Abuja), it says so. |
| Admin auth | `api/admin/_auth.mjs → requireAdmin` (Supabase session; only aderintomicheal6@gmail.com plus `shop_admins`). | Reused for the inbox and knowledge-base endpoints in `api/admin/manage.mjs`. |
| Serverless | Vercel Hobby, 12 functions (the limit is reached). | No new function: `/api/assistant` and `/api/whatsapp` are rewrites to `api/shop/settings.mjs?op=…`. Server modules start with `_`, so they don't count as functions. |
| Email | `commerce/email.mjs` sends through Resend; nothing is sent when `RESEND_API_KEY` is missing. | Reused for one email per handed-over chat to the owner. That email has no customer contact details. |
| Existing chat/WhatsApp | Only `wa.me/2347086865133` links; no chat widget. | The WhatsApp link stays as the always-available fallback and carries a structured summary. |
| Policies | Warranty, refund, delivery, terms and privacy pages in `commerce/policies.mjs`; payment options in checkout. | These are the only sources for the knowledge base. Anything not found there is marked *needs confirmation* (see §5). |

## 2. Architecture

```
Browser (assets/assistant-launcher.js → assets/assistant.js)
   │  POST /api/assistant  {action: start | message | poll | handoff}
   ▼
api/_assistant.mjs  — conversation service (channel-agnostic)
   │  rate limits · sessions · consent · lead record · handoff email · budget guard
   ├── simulation (default): commerce/assistant.mjs → simulate()
   └── openai (opt-in):      api/_ai-openai.mjs → OpenAI SDK + read-only tools
            tools → commerce/assistant.mjs: searchCatalogue · knowledgeFact · delivery fee
api/_ai-whatsapp.mjs — WhatsApp Cloud API adapter (disabled) → same service
api/admin/manage.mjs — inbox + knowledge base (admin only)
```

- **Prices are never written by the model or the simulator.** Product cards are built by the server from catalogue rows. In OpenAI mode, every ₦ amount in the model's reply must match a price, fee or budget from a tool or from the customer. Otherwise the reply is discarded and the simulator answers instead.
- **Customer text can't change anything.** No customer message can modify the database, discounts, payments or admin settings. A customer can only affect their own conversation's context.
- **Prompt-injection defences:**
  - the system prompt stays on the server;
  - customer text is only ever a `user` message;
  - tool output is treated as data;
  - the simulator refuses "ignore your instructions"-style requests.

## 3. Supabase migration

`supabase/migrations/20261121170000_mikee_ai.sql` is additive only.

**New tables.** RLS is on with no policies, and anon/authenticated have no grants.
- `shop_assistant_conversations`: conversations and leads.
- `shop_assistant_knowledge`: admin edits to the knowledge base.
- `shop_assistant_rate`: rate-limit windows.
- `shop_assistant_usage`: AI calls and estimated cost per day.
- `shop_assistant_wa_events`: WhatsApp duplicate protection.

**New functions.** All are revoked from public, anon and authenticated.
- `shop_assistant_hit`
- `shop_assistant_record_usage`
- `shop_assistant_purge`

**Daily retention job.** pg_cron runs `mikee-assistant-retention` at 03:17.
- Chats with no consent are deleted after 30 days.
- After 180 days, contact details, WhatsApp ids and transcripts are cleared.

**Privacy.**
- The browser keeps a random 32-byte token. Only its SHA-256 is stored.
- IP addresses are stored only as salted hashes.
- Phone numbers and emails are kept only after the customer ticks the consent box. Without consent they are redacted from the transcript.

## 4. Environment variables (server only — never in browser code)

| Variable | Default | Purpose |
|---|---|---|
| `MIKEE_AI_MODE` | `simulation` | `openai` turns on the OpenAI provider. Any other value means simulation. |
| `OPENAI_API_KEY` | — | Needed for OpenAI mode. Without it, the simulator answers. |
| `OPENAI_MODEL` | `gpt-4.1-nano` | Any chat model that supports tool calling. |
| `OPENAI_MAX_OUTPUT_TOKENS` | `350` | Output cap per call (hard ceiling 800). |
| `MIKEE_AI_MONTHLY_BUDGET_NGN` | `8000` | Calls stop for the month at this estimated spend. The simulator then answers. |
| `MIKEE_AI_DAILY_CALLS` | `400` | Daily cap on model calls. |
| `OPENAI_INPUT_USD_PER_M` / `OPENAI_OUTPUT_USD_PER_M` / `USD_NGN_RATE` | `0.5` / `2` / `1700` | Cost estimate. Set deliberately high so the cap trips early. Set the real rates when you activate. |
| `MIKEE_AI_HASH_SALT` | derived | Salt for IP and WhatsApp-id hashes. |
| `RESEND_API_KEY` | — (existing) | Handoff alert emails. Nothing is sent without it. |
| `WHATSAPP_ENABLED` | — | Must be `true` (plus the four values below) to enable the WhatsApp webhook. |
| `WHATSAPP_VERIFY_TOKEN`, `WHATSAPP_APP_SECRET`, `WHATSAPP_ACCESS_TOKEN`, `WHATSAPP_PHONE_NUMBER_ID` | — | Meta Cloud API credentials (see §8). |

The existing `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` and `SHOP_ORIGIN` are reused.

**Limits that apply in every mode:**
- 30 messages per connection every 10 minutes.
- 8 new chats per connection per hour.
- 3,000 messages per hour across the store.
- 60 messages per chat.
- 500 characters per message.
- Model calls only: 20 per chat, the last 12 messages as context, at most 3 tool rounds, and a 12-second timeout.

## 5. Knowledge base — what needs your confirmation

Open **Admin → Mikee AI → Knowledge base**. Only entries marked **Verified** are stated as facts. These defaults could not be confirmed from the site, so Mikee AI tells customers the team will confirm them:

- Opening hours
- Credit Direct approval criteria
- Swap valuation amounts
- Device checks (iCloud, activation, originality)
- Discount thresholds

The price-objection replies are templates; please review the wording. To publish an entry, fill in its text, set it to **Verified** and tap **Save**. Mikee AI uses the change within a minute.

## 6. Admin conversation inbox

To open it, sign in at `/admin/` and choose the **Mikee AI** tab.

**What it shows**
- Chats that need a person come first: the customer asked for one, a complaint, a payment problem or a price-review request.
- Unread counts and a badge on the tab.
- Lead details. Contact details appear only when the customer gave consent.

**What you can do**
- Open a chat to read it; this marks it as read.
- Reply. On the website, your reply appears in the customer's chat window within about 15 seconds. Replying pauses Mikee AI for that chat.
- Pause or resume Mikee AI.
- Mark a chat as handled.
- Set the status and add private notes.

**Statuses:** New, Exploring, Interested, Ready to buy, Needs a person, Converted, Closed.
- Statuses update automatically from what the customer actually said.
- **Converted** can only be set by you, with the reference of an order that is paid (or a reservation completed and paid).

## 7. Testing simulation mode

**Automated tests:** `npm run check` runs lint, build and all tests. `tests/mikee-ai.test.mjs` covers the 20 required areas plus the WhatsApp adapter and the website integration.

**Manually on a preview deployment:**
1. Open any product or category page and tap **Mikee AI**. A "Demo mode" label shows in the header.
2. Try these messages:
   - "How much is iPhone 13?"
   - "What about 256GB?"
   - "Too expensive abeg 😂"
   - "my budget na 350k"
   - "delivery to lekki"
   - "UK used vs brand new?"
   - "I want to talk to a person"
3. In Admin → Mikee AI, open the chat and reply. The reply appears in the customer's window.

Simulation never calls OpenAI, even when a key is present. This is covered by test 20.

## 8. Activating OpenAI (after you add API credit)

1. In the OpenAI dashboard, set a **hard monthly budget**, e.g. the naira equivalent of ₦8,000. This is your real safety net.
2. In Vercel → Project → Settings → Environment Variables, add the following for **Preview** first:
   - `OPENAI_API_KEY`
   - `MIKEE_AI_MODE=openai`
   - optionally `OPENAI_MODEL`, the budget variables and the real per-token rates.
3. Redeploy the preview. Chat with it; the "Demo mode" label disappears.
4. Check `shop_assistant_usage` in Supabase to see calls and estimated naira cost per day.
5. Only after you are happy, add the same variables to **Production**.

To switch off, set `MIKEE_AI_MODE=simulation` or remove the key.

## 9. WhatsApp Cloud API (prepared, disabled)

The adapter (`api/_ai-whatsapp.mjs`) supports:
- webhook verification and `X-Hub-Signature-256` HMAC checks;
- parsing of text and button replies, and de-duplication by message id;
- conversation mapping by a salted hash of the sender;
- the 24-hour customer-service window: admin replies outside it are refused, because only approved templates are allowed then;
- human handoff and pause/resume, the same as on the website;
- outgoing text formatting (products become short lines with links).

No unofficial WhatsApp Web automation is used.

**Before activation you need:**
1. A Meta Business account (verified), a Meta developer app with the WhatsApp product, and a WhatsApp Business Account.
2. A phone number registered on the Cloud API. Your current number (0708 686 5133) may be in use on the WhatsApp Business app; moving it, or using coexistence, depends on Meta's eligibility rules for that number. Check this in Meta Business Manager. A new dedicated number is the simplest path.
3. A permanent System User access token with `whatsapp_business_messaging` permission, plus the phone number ID, the app secret and a verify token you choose.
4. Approved message templates if you want to message customers more than 24 hours after their last message.
5. Webhook URL `https://www.mikeegadget.com.ng/api/whatsapp`, subscribed to the `messages` field.

**Technical check before go-live.** Meta's signature must be computed over the raw request body. The adapter refuses any request whose raw body it can't read. On a preview, confirm that Vercel passes the raw body through the shared function. If not, the webhook needs its own function, which means freeing one of the 12 Hobby slots or upgrading the plan.

## 10. Known limitations

- Simulation mode is rule-based. It understands common shopping phrasing, Pidgin and follow-ups, but not everything. When it can't help, it says so and offers a person.
- Comparisons cover only catalogue facts: price, storage, condition and SIM. Detailed specs are referred to the team.
- Handoff emails need `RESEND_API_KEY`.
